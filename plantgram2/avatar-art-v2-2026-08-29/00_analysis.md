# 식물 아바타 아트 v2 — 자료 분석

레퍼런스 아이소메트릭 온실 일러스트 5장에서 **식물 요소만** 뽑아 우리 아바타에 이식하기 위한
사전 분석. 구조물(유리 온실 프레임·바닥)은 이미 `garden-sim`에 있으므로 이번 범위 밖.

---

## 1. 우리 자산 현황 (as-is)

### 1.1 아바타 아트 소스가 3벌로 갈라져 있다

| 위치 | 정체 | 상태 |
|---|---|---|
| `garden-kit-2026-08-26/src/parts.mjs` | 자칭 SSOT. 8형태×4단계, `manifest.json` + PNG 스프라이트 빌드 | **가장 오래됨 / 가장 안 예쁨** |
| `garden-sim-2026-08-26/index.html` (인라인 `FORMS`) | parts.mjs를 복사해 개선한 판 | **현재 최고 품질** |
| `mockup-v3-2026-08-26/index.html` (인라인 `plant()`) | 또 다른 축소 복사판 | 카드용 미니 렌더 |
| `app/main.dart.js` (Flutter 빌드) | 위 셋 중 어느 것도 안 씀. 자체 렌더러 | 소스가 두 저장소에 없음 |

`garden-sim`이 `parts.mjs`보다 앞서 있는 지점:
- `toneGrads()` — 잎에 선형 그라디언트(밝은 면 → 베이스 → 어두운 면)
- 잎 외곽 음영선 `rgba(20,40,26,.22)`
- 화분 몸통/림 그라디언트, 흙 radial 그라디언트, 림 안쪽 그림자 아크
- 줄기(`stem()`) 추가 — 잎이 공중에 떠 있지 않음
- 9번째 형태 `flower`(꽃나무) 추가 — parts.mjs에는 없음

→ **개선한 내용이 SSOT로 역류하지 않았다.** 지금 `manifest.json`과 PNG 스프라이트는 구버전 아트다.

### 1.2 실제 버그: 깃꼴형(palm)이 안 그려짐

`parts.mjs` 의 palm 프론드 정의가 `[[0, -1.0], [-26, -.86], ...]` — 길이 값이 **음수**다.
`H = 52 * len` 이 음수가 되어 `M0,0 L0,52`, 즉 잎이 **화분 아래(지면 밑)로** 그려진다.

- 카탈로그 깃꼴형 4칸이 전부 빈 화분
- `dist/sprites/palm_s1.png` 와 `palm_s2.png` 가 바이트까지 동일(10,752 B) — 둘 다 사실상 빈 그림
- `garden-sim` 쪽 같은 배열은 양수(`[[0,1],[-26,.86],...]`) → 복사 과정에서 부호가 유실된 것

### 1.3 아트 자체의 약점 (레퍼런스 대비)

1. **잎이 3~5장.** 레퍼런스는 한 그루당 12~25장이 겹쳐서 볼륨을 만든다.
2. **잎 실루엣이 사실상 1종.** `leafBlade()` 물방울 하나를 회전·스케일해 8형태를 전부 파생시킴.
   멀리서 보면 대엽형·덩굴형·무늬엽형이 구분되지 않는다.
3. **단색 평면 채움**(parts.mjs). 조명 방향이 없어 아이소메트릭 씬에 얹으면 납작하다.
4. **채도가 낮다.** 우리 기본 초록 `#3f7d54` 는 세이지 계열. 레퍼런스는 `#84c054` 같은 밝은 연두다.
5. **흙·화분 디테일 없음.** 흙은 단색 타원, 화분은 재질감 없음.
6. **그림자가 타원 1개.** 접지감이 약하다.

## 2. 레퍼런스에서 뽑을 요소

이미지 5장을 300×300으로 리샘플해 HSV 마스킹(초록 `h∈(0.20,0.45)`, 갈색 `h∈(0.02,0.13)`)으로
지배색을 뽑은 결과:

| 레퍼런스 | 초록 상위색 | 갈색(화분/흙) 상위색 |
|---|---|---|
| #5 아치형 온실 | `#84c054` `#90cc60` `#60b424` / 대비 `#243024` | `#544830` `#605430` |
| #2 대형 온실 | `#a8ccc0` `#c0e4d8` `#54d8a8` | `#6c603c` `#c0a860` |
| #3 흰 프레임 | `#90b49c` `#9cc0a8` `#6c9c78` | `#ccb484` `#cc9c60` `#d8a86c` |
| #1 목재 기단 | `#607830` `#6c8430` `#78903c` | `#90603c` `#9c6c3c` `#b48448` |

### 2.1 조형 규칙 (크롭 관찰)

- **잎 실루엣이 종마다 완전히 다르다.** 갈래잎(제라늄·단풍형), 둥근 수련잎, 넓은 하트잎,
  가늘고 긴 창잎, 톱니 허브잎 — 최소 5~6종의 실루엣이 한 화면에 공존한다.
- **밝은 연두 + 어두운 초록의 강한 대비.** 중간톤만 쓰지 않는다.
- **조명 방향이 고정**(좌상단). 잎마다 밝은 면/어두운 면 2톤이 같은 방향으로 들어간다.
- **겹침으로 볼륨.** 뒤쪽 잎은 어둡게, 앞쪽 잎은 밝게 — 2패스 레이어링.
- **화분**: 테라코타 `#cc9c60`~`#d8a86c`, 림에 두께가 있고 안쪽에 그늘이 진다.
- **플랜터 박스**(직사각 아이소 박스)에 식물 여러 그루가 심긴 구성 — 우리 벤치/선반 슬롯에 대응.
- 밖에는 **관목/작은 나무**가 화분 없이 흙 베드에 심겨 있다 — 우리에 없는 요소.

### 2.2 뽑지 않을 것

- 유리 패널의 반사/굴절 표현 — 이미 `garden-sim` 프레임으로 충분하고, 40칸 얹으면 비싸다.
- 사진 같은 텍스처·워터마크 이미지 자체 — 우리는 좌표+파츠 ID만 전송하는 구조를 유지해야
  방문 기능과 즉시 커스텀이 가능하다(`concept-iso-garden` 문서에서 이미 내린 결론).

## 4. 전략 옵션

| | 내용 | 비용 | 결과 |
|---|---|---|---|
| A | `parts.mjs`를 `garden-sim` 수준으로만 되돌림 | 낮음 | 버그·중복은 해결, 레퍼런스와 격차는 그대로 |
| B | **`parts.mjs`를 진짜 SSOT로 승격 + 아트 레이어 v2 리라이트** | 중간 | 권고 |
| C | 실제 PNG/SVG 아트 에셋 도입 | 높음 | 방문 기능·즉시 커스텀 이점 상실 |

**권고: B.** 파라메트릭 코드 유지가 이 제품의 전제(남의 정원을 열 때 이미지를 한 장도 안 받는 구조)라
C는 이미 기각된 방향이고, A는 사용자가 지적한 "안 예쁘다"를 해결하지 못한다.

## 5. 실행 계획

### Phase 0 — 통합 · 버그 (기반)
- `garden-sim`의 개선분을 `parts.mjs`로 역류시켜 SSOT 일원화
- `flower`(꽃나무) 형태를 SSOT에 승격 → 형태 8종 → 9종
- palm 부호 버그 수정, 스프라이트 재빌드
- `garden-sim` / `mockup-v3` 가 인라인 복사본 대신 `dist/parts-browser.mjs` 를 import
- **검증**: 카탈로그 9×4 = 36칸 전부 그림이 있을 것

### Phase 1 — 팔레트 v2
- `LEAF_TONES` 를 `{hi, base, shadow, vein}` 4값으로 확장, 레퍼런스 추출값 기준으로 채도 상향
- `POT_COLORS` 테라코타를 `#cc9c60`~`#d8a86c` 대역으로 재조정
- **검증**: 정원 씬에서 기존 대비 나란히 비교

### Phase 2 — 잎 라이브러리
- 단일 `leafBlade()` → 실루엣 6종 파라메트릭 함수:
  `ovate`(넓은 타원) / `cordate`(하트) / `lanceolate`(창) / `palmate`(갈래) / `round`(수련) / `serrate`(톱니)
- 형태 9종이 각자 잎 종류를 지정
- **검증**: 실루엣만(단색 검정)으로 뽑았을 때 9종이 서로 구분될 것

### Phase 3 — 볼륨 · 라이팅
- 잎 배열을 2패스로: 뒤 레이어(shadow 톤) → 앞 레이어(hi 톤), 잎 수 2~3배
- 좌상단 고정 광원 규약 — 모든 파츠가 같은 방향
- 줄기 곡선 + 식물 ID 기반 결정론적 지터(같은 식물은 항상 같은 모양)
- **검증**: 정원에 20그루 배치해도 프레임 예산 안에 들 것

### Phase 4 — 화분 · 흙 · 접지
- 림 두께/안쪽 그늘, 재질 3종(테라코타 무광 / 유광 / 시멘트)
- 흙 표면 알갱이·자갈 파츠
- 접지 그림자 2단(코어 + 소프트)

### Phase 5 — 정원 씬 요소 (선택)
- 플랜터 박스(직사각 아이소) 슬롯 — 레퍼런스의 재배 베드
- 화분 없는 흙 베드 관목 — 마당 슬롯용

### 유지할 계약
- 아바타 저장 데이터 `{form, stage, pot, potColor, tone, prop, state}` — 그대로
- 파츠 원점 = 지면 접점, 위가 y 음수 — 그대로
- `GRID {tileW:78, tileH:39, zH:44}` — 그대로
- `manifest.json` 은 필드가 추가될 뿐 기존 필드는 유지 → `version: 2`

## 6. 열린 결정 사항

1. **Flutter 앱 반영 경로.** 앱 렌더러 소스가 이 두 저장소에 없다. HTML 프로토타입만 고치면
   앱에는 안 들어간다 — 앱 소스 저장소를 세션에 붙일지 결정 필요.
2. **형태 수.** 9종 유지 vs 레퍼런스처럼 관목·허브를 더할지.
3. **성장 단계.** 4단계 유지 vs 잎 수를 늘리는 김에 단계 간 차이를 더 벌릴지.
