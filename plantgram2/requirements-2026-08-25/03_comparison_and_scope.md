# 비교 검토 — 레거시 기능 전수 vs 차기 버전 채택 여부

> 레거시(01 문서)의 모든 기능을 항목별로 검토하고, preview 3개 이터레이션(02 문서)의 결론과 대조하여
> **채택 / 개선 채택 / 보류 / 제외**를 판정한 매트릭스.
> ✅ 채택(코어) · 🔧 개선하여 채택 · ⏸ 보류(출시 후 검토) · ❌ 제외

## 1. 식물 관리 (레거시 MY 식물 ↔ 차기 내 식물)

| 레거시 기능 | 판정 | 근거 / 차기 반영 방식 |
|---|---|---|
| 식물 등록 (식물종 선택 + 관리 기준) | ✅ | 코어 중의 코어. plantgram2의 11항목 기준 계승 |
| 물주기 D-Day + 물결 게이지 | 🔧 | D-Day 유지. 물결 게이지는 레거시의 최고 시그니처 UI — 차기에도 재현 가치 있음 |
| 원터치 물주기 + 확인 다이얼로그 | ✅ | plantgram2에도 구현됨 |
| **일괄 물주기** | ✅ | 레거시·plantgram2 양쪽에 존재 — 검증된 편의 기능 |
| 활동 기록 8종 (물/햇빛/통풍/분갈이/영양/가지/분무/관찰) | 🔧 | plantgram2는 6종(물/영양제/분갈이/메모/상태/사진)으로 축소. **6종 채택**, 햇빛·통풍·분무·가지는 메모/상태로 흡수 (결정 필요 → 04 문서 D-3) |
| 상태 기록 8종 (좋음~추움) | 🔧 | plantgram2는 3단계(좋음/보통/관심 필요)로 축소 채택. 세분화는 AI 메모 분석으로 대체 가능 |
| 스케줄 캘린더 (월간) | 🔧 | plantgram2는 "일정 탭"(다가오는 예정 리스트)으로 단순화. 월간 캘린더는 확장 후보 |
| 앨범 (사진 그리드 + 타임라인) | 🔧 | plantgram2 다이어리 탭이 계승. 성장 기록 갤러리는 차별화 요소로 유지 |
| 통계 (도넛/막대 차트) | ⏸ | AI 주간 요약(AI-2)이 상위 대체재 |
| 메모 5카테고리 + 이웃 메모 복사 | ❌ | 구조 과잉. 단일 메모 + AI 요약으로 대체 |
| 식물종별 Tips | ✅ | plantgram2 사전 상세의 `plant_tips`로 계승됨 |
| AI 추천 (유사 식물) | 🔧 | plantgram2 사전 상세 "비슷한 식물"로 계승 |
| QR 코드 물주기 | ❌ | 3개 이터레이션 모두 제외 합의. 하드웨어(스티커 판매) 의존 기능 |
| 식물 죽음 처리 | 🔧 | plantgram2 "관리 종료/재시작"이 더 나은 모델 (복구 가능) |
| 식물 복원 (재설치 시) | ✅ | **필수**. 단, 레거시처럼 로컬 우선이 아니라 서버(Firestore) 원본으로 설계하면 자동 해결 |
| 레거시엔 없던 것: 레벨 시스템(Lv.N), 날씨 카드 | 🔧 | plantgram2 신규 요소. 채택 여부 결정 필요 (04 문서 D-4, D-5) |

## 2. 소셜 (레거시 피드/커뮤니티/프로필 ↔ 차기 커뮤니티)

| 레거시 기능 | 판정 | 근거 |
|---|---|---|
| 인스타형 사진 피드 (팔로우/좋아요/댓글) | ❌ | 3개 이터레이션 모두 제외. 운영 부담(신고/차단/모더레이션) 대비 관리 루프 기여 낮음 |
| 팔로우/팔로잉/친구찾기 | ❌ | 피드 제거와 함께 제외 |
| 해시태그 큐레이션 | 🔧 | 피드용은 제외, **사전 추천 섹션**(#초보집사 #공기정화 등 8종 → plantgram2 10종)으로 계승 |
| 식물종별 게시판 (커뮤니티 탭) | 🔧 | **식물 맥락형 커뮤니티**로 축소 계승 (사전 상세에서 진입, 독립 탭 아님) |
| 답변 랭킹 | ⏸ | 커뮤니티 활성화 이후 검토 |
| 댓글/대댓글 + 푸시 | 🔧 | 식물별 커뮤니티에 1단 댓글로 축소 (plantgram2 구현 완료: 댓글 수 집계 + 푸시 Functions) |
| 신고/차단/숨김 | 🔧 | 커뮤니티가 남는 한 최소한의 신고/차단은 앱스토어 심사 요건. AI 유해표현 필터는 후순위 보조 |
| 이웃식물 / 이 식물을 키우는 사람들 | ✅ | plantgram2 "키우는 사람들" 섹션 + `is_public` 공개 설정으로 계승 |
| 프로필 (bio/웹사이트/게시물 그리드) | ❌ | 계정 = 최소 설정 5종으로 축소 |

## 3. 커머스/O2O (레거시 마켓·상점·상담 ↔ 차기 없음)

| 레거시 기능 | 판정 | 근거 |
|---|---|---|
| 중고거래 마켓 + 1:1 채팅 | ❌ | 3회 제외 합의. 채팅 인프라 유지 비용 큼 |
| Shop (상품/클래스 판매) | ❌ | 동일 |
| 전문가 상담 (텍스트/영상) + 인앱결제 | ❌ | 레거시에서도 결제 전체 비활성이었음 — 시장 검증 실패 신호 |
| 출장서비스 4종 견적 | ❌ | 동일 |
| 스마트스토어 연동 / QR 상품 | ❌ | QR 제외와 함께 |
| 매거진 (블로그/유튜브) | ⏸ | 콘텐츠 큐레이션 자체는 가치 있으나 운영 리소스 필요. 사전 팁 콘텐츠로 흡수 후 검토 |
| 광고 (AdMob + 자체 슬라이드) | ⏸ | MVP는 무수익. 수익화는 별도 결정 (04 문서 D-7) |
| 어드민 화면 | ❌ | 앱 내 어드민 대신 Firebase 콘솔/웹 대시보드 |

## 4. 계정/시스템

| 레거시 기능 | 판정 | 근거 |
|---|---|---|
| 소셜 로그인 5종 + 이메일 | 🔧 | **Kakao 단일**로 축소 (3회 합의). 단, iOS 출시 시 Apple 로그인 심사 요건 → 결정 필요 (04 문서 D-1) |
| 게스트 모드 (비로그인 식물관리) | ⏸ | 레거시의 진입장벽 낮추기 전략. plantgram2는 로그인 필수 — 결정 필요 (04 문서 D-2) |
| 물주기 푸시 (시각 6슬롯) | 🔧 | plantgram2는 단일 시각 선택(09:00)으로 단순화 채택 |
| 다국어 (ko/en) | ⏸ | 레거시도 사실상 ko 전용. MVP는 ko 단일 |
| 로컬 SQLite 우선 + 서버 동기화 | ❌ | 마이그레이션 지옥의 원인. Firestore 단일 원본 + 오프라인 캐시로 대체 |
| 이용약관/개인정보 동의 | ✅ | 필수 유지 |
| 리뷰 유도 (7회 접속 + 물주기 직후) | 🔧 | 타이밍 전략은 좋았음 — 물주기 성공 직후 유도 재활용 |
| 앱 재설치 대비 복원 | ✅ | 서버 원본 구조로 자동 해결 |

## 5. 요약: 차기 버전에서 잘라낸 것 / 남긴 것 / 새로 얻는 것

**잘라냄 (레거시 5탭 중 3탭 분량)**: 인스타형 피드, 팔로우 그래프, 중고거래+채팅, Shop, 전문가상담+결제, 출장서비스, QR, 매거진, 광고, 어드민 앱, 5종 소셜 로그인, 로컬 DB 동기화

**남김 (관리 루프)**: 식물 등록 → 돌봄 주기(물/영양제/분갈이) → 기록 6종 → 일정/다이어리 → 사전(추천+팁) → 식물 맥락 커뮤니티 → 최소 계정

**새로 얻음 (레거시에 없던 것)**: AI 자연어 기록 초안, AI 주간 요약, 날씨 연동 카드, 레벨 시스템, 관리 종료/재시작, 단일 서버 원본(재설치 걱정 없음)
