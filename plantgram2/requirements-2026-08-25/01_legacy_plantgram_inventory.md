## 1. 앱 개요

### 기술 스택
| 항목 | 내용 |
|---|---|
| 프레임워크 | Flutter 1.22.6, Material Design |
| 상태관리 | provider + get 혼용, 전역 변수 + `setState` 직접 호출 |
| 다국어 | easy_localization (ko/en, 기본 ko) |
| 로컬 DB | sqflite — `MyPlantDB.db` (schema v9), 이미지 Base64 저장 |

### 백엔드 (이중 구조)
1. **자체 Node 서버** (`http://34.64.105.173:3000`, 평문 HTTP)
   — 식물종 도감, 커뮤니티 게시판, 메모, Tips, 매거진, 통계, 랭킹, 배너, 푸시 설정, 사용자 채번 (엔드포인트 약 65개)
2. **Firebase** (0.x 세대)
   — Firestore: 소셜 피드 / 중고마켓 / 상담 / 채팅
   — Auth, Storage(이미지), FCM(푸시), Analytics

### 인증
- 이메일/비밀번호 + 소셜 5종: Google / Facebook / Apple / **Kakao** / **Naver** (Kakao·Naver는 자체 콜백 서버 → Firebase Custom Token)
- **게스트 모드**: 식물관리·식물사전은 로그인 없이 사용 가능
- 회원가입 시 이용약관 체크 필수, 회원탈퇴 지원

### 수익화
| 유형 | 상태 |
|---|---|
| AdMob 배너 | 블로그 매거진 본문 1곳만 활성 |
| 자체 네이티브 광고 슬라이드 (Firestore `ad` 컬렉션) | 활성 — 피드 5개마다, 커뮤니티 7개마다 삽입 |
| 인앱결제 (1:1 전문가 상담) | **전체 주석 처리 (비활성)** |
| 네이버 스마트스토어 연동 (QR 식물관리 상품) | 활성 |
| 출장서비스 견적 접수 | 활성 (문의 접수형) |

## 3. 메뉴별 기능 상세

### 3-1. MY 식물 (탭 0)

**「식물」 서브탭**
- 등록 식물 리스트 (SQLite 로컬 우선)
- 물주기 D-Day + `LiquidLinearProgressIndicator` 물결 게이지로 경과율 시각화
- 카드별 물주기 원터치 버튼 (확인 다이얼로그 → 완료 스낵바)
- **일괄 물주기**: 물 줄 식물이 있으면 상단 말풍선 + 카운트 뱃지
- 일조량/물선호도 별점형 5단계 표시 (해/물방울 아이콘)
- 죽음 처리된 식물 구분 표시
- 식물명 검색, 빈 상태 온보딩 화면("누구나 / 쉽고 예쁘게 / 키울 수 있도록.")
- 식물 복원하기 (앱 재설치 시 서버에서 로컬 DB 재구성)

**식물 등록 폼** (SlidingUpPanel)
- 식물종 선택(서버 도감 검색) → 미선택 시 이웃 통계 기반 관리 정보 자동 제안
- 사진 (3해상도 압축, 로컬 Base64 + Storage 업로드)
- 식물이름(필수) / 마지막 물준날 / 물주기·영양제·분갈이 주기 휠 피커 / 일조량·물주는양 별점 / 생육온도 범위
- 추가 상세: 마지막 영양제·분갈이, 처음 함께한 날, **QR코드 연결**

**식물 상세** (`WaterDetailPage`, 4,458줄 — 앱 최대 화면)
- 히어로 이미지 + D-Day → 좋아요 → 관리 지표 → 물주기·영양제·분갈이 D-Day 3분할
- **메모** (5카테고리: 식물관리/식물특징/물선호/빛선호/온도 + 이웃 메모 복사·붙여넣기)
- **Tips** (식물종별 관리 팁) → **통계** (도넛 차트) → **다이어리** (활동 타임라인)
- **AI 추천** (물주기/물선호도/빛선호도/최저온도 유사 식물)
- **이웃식물** / **새소식**(해당 식물종 피드) / **게시글**(식물종별 게시판)
- 예쁘게 캡쳐해서 공유하기 (스크린샷 + share)
- 스토리에 함께 올리기 (활동 기록을 피드에 동시 게시)

**활동(Action) 기록 체계**
- 활동 8종: 물주기 / 햇빛 / 통풍 / 분갈이 / 영양 / 가지 / 분무 / 관찰
- 상태 8종: 좋음 / 보통 / 아픔 / 죽음 / 새싹 / 개화 / 마름 / 추움
- 각 코드에 전용 파스텔 컬러 매핑

**「스케줄」 서브탭**: `table_calendar` 월간 캘린더, 날짜별 활동 마커, 미래 물주기 예정 표시

**「앨범」 서브탭**: 활동 사진 가로 스크롤 → Staggered Grid → 상세 / `timeline_tile` 세로 타임라인

**QR 식물관리**: 스마트스토어에서 QR 스티커 구매 → 식물에 연결 → QR 스캔으로 즉시 물주기 기록

### 3-2. Plantgram 피드 (탭 1)
- 무한 스크롤 피드 (BLoC 페이징), 게시물: 다중 이미지 / 본문 / 좋아요 / 댓글·대댓글 / 내식물 태그 칩
- 팔로우 기반 피드 (작성 시점 팔로워 스냅샷 방식 — 팔로우 이후 게시물만 표시)
- 인기 탭: 해시태그 큐레이션 그리드 / 인기 피드 / **중고거래 섹션**
- 게시물 작성: 사진 최대 3장 + 식물종 태그 + 내식물 태그 최대 3
- 신고/차단/숨김 처리, 댓글 푸시 알림
- 광고 5개마다 삽입

### 3-3. 식물사전 (탭 2)
- 검색 (식물사전/새소식 탭, 검색어 하이라이트)
- 누적 식물 수 롤링 카운터 ("N 그루의 이웃 식물들과 함께해요")
- **해시태그 큐레이션 8종**: #초보집사 #공기정화 #반려동물 #집꾸미기 #게으른 #어두운집 #물조금만 #겨울나기
- 오늘의 식물 / 최신등록 / 실시간 인기식물 (3일 랭킹)
- 하단 메뉴 4종: 식물사전 / 식물영상(유튜브 매거진) / 식물블로그 / QR식물관리
- 식물종 상세: 물주기·위치·햇빛·물·온도 → Tips → 이웃메모 → AI 추천 → 이웃식물 → 새소식 → 게시글

### 3-4. 커뮤니티 (탭 3)
- **식물종별 게시판** + 자유게시판, 카테고리 드롭다운 + 검색
- 글쓰기(BottomSheet), 댓글/대댓글, 조회수/좋아요
- **답변 Ranking** (커뮤니티 기여 랭킹) 리스트 중간 삽입
- 신고/차단, 광고 7개마다 삽입

### 3-5. 프로필 (탭 4)
- 게시물/팔로우/팔로잉 카운트, bio(URL 자동 링크), 웹사이트 링크
- 채팅 아이콘 + 미읽음 빨간 뱃지, 직거래 새 메시지 알림 배너
- 프로필 수정 / 친구찾기 / 팔로우 관리
- **Shop 관리** (seller 플래그 유저만): 상품/클래스 등록·판매
- 그리드(내 게시물) ↔ 리스트(내 식물) 토글
- 햄버거 메뉴: 로그인/로그아웃/회원탈퇴, 설정(언어·푸시 시간 6슬롯), 이용안내, 노하우 공유, 리뷰쓰기, 문의하기(메일), SNS 링크

### 3-6. 중고거래 마켓 (피드 → 진입)
- 탭 5: 마켓 / 내상품 / 판매완료 / 관심상품 / 출장서비스
- 상품 등록: 사진 3장 / 제목 / 가격 / 판매주소(카카오 주소검색) / 식물종 카테고리 / 내식물 태그
- 상세: 관심 N개 / 채팅 N개 / **채팅으로 거래하기** / 거래완료 변경 / 키우는 식물 보러가기
- 중개자 면책 고지 문구 포함

### 3-7. 채팅
- 거래 상품 카드가 상단에 붙는 1:1 채팅 (말풍선 UI)
- 텍스트/이미지 전송, 미읽음 관리, 대화 삭제
- 메시지를 양방향 2벌 중복 저장 (구조적 이슈)

### 3-8. 전문가 상담 / 출장서비스 (진입점 대부분 주석 처리)
- 1:1 텍스트 상담 (증상/환경/물주기 + 사진) / 영상·음성 상담 (연락처 + 예약)
- 출장서비스 4종 (분갈이·교체 / 치료·처방 / 식물이사 / 식물보관) — 지역별 출장비 + 화분 크기 단가 자동 견적
- 전문가 답변: 진단/치료방법/예방법 3필드 + 푸시
- 인앱결제 코드 존재하나 전체 비활성

### 3-9. 매거진 / 이벤트 / 어드민
- 식물 매거진 Blog / Youtube (서버 큐레이션 콘텐츠, AdMob 실노출 위치)
- 서버 배너 → 이벤트 페이지 (외부 링크/상세 이미지)
- 어드민: 상담 관리 4탭 (현재 비활성)

## 5. 알려진 이슈 (차기 버전 참고)

1. 주석으로 죽어 있는 기능 다수 — 인앱결제, 어드민, 전문가상담·출장·쇼핑 진입 메뉴
2. 전역 mutable 변수 + 타 화면 `setState` 직접 호출 — 상태관리 전면 재설계 필요
3. 평문 HTTP 자체 서버 — HTTPS 전환 필수
4. 운영자 이메일·좋아요 가중치 하드코딩
5. 피드가 작성 시점 팔로워 스냅샷 방식 — 팔로우 이전 게시물 안 보임
6. 채팅 메시지 2벌 중복 저장, 이미지 Base64 SQLite 저장 — 비용/성능 부담
7. 초대형 파일 (식물 상세 4,458줄 / 커뮤니티 5,025줄)
8. Flutter 1.22 / Firebase 0.x — 전면 마이그레이션 없이는 빌드 불가 수준의 노후화
9. 다수 오타 및 en 번역 미적용 하드코딩 문자열
