# 차기 플랜트그램 — 설계 정의 (초안 v0.1)

> 01(레거시 인벤토리) + 02(preview 3개 이터레이션) + 03(비교 매트릭스)을 종합한 제안.
> 아직 **초안**이며, 하단 "결정 필요 항목(D-1~D-8)"에 답하면 v1.0으로 확정한다.

## 1. 제품 정의

**한 문장**: "내 식물을 등록하면, 물 줄 때를 알려주고, 말로 하면 기록해주는 반려식물 관리 앱"

**핵심 루프**: 등록 → 오늘 할 일 확인(푸시) → 원터치/자연어 기록 → 다이어리·요약으로 성장 확인 → (사전·커뮤니티로 궁금증 해결) → 반복

**하지 않는 것** (3개 이터레이션 합의 + 레거시 교훈):
- 인스타형 피드/팔로우 그래프 ❌
- 커머스 전부 (중고거래, 쇼핑, 클래스, 상담 결제) ❌
- QR 하드웨어 연동 ❌
- AI 자동 저장 ❌ / 이미지 질병 진단 ❌ / 범용 상담 챗봇 ❌ (출시 후 검토)
- 앱 내 어드민 ❌

## 2. 정보 구조 (IA)

**하단 4탭** (3개 이터레이션에서 불변 검증):

```
[내 식물]           [사전]              [기록]               [계정]
 ├ 내식물 탭         ├ 검색              ├ 자연어 입력(AI)      ├ 프로필/닉네임
 ├ 일정 탭           ├ 오늘의 식물        ├ 필터 7종            ├ 알림(on/off+시각)
 ├ 다이어리 탭        ├ 추천 섹션 10종     ├ 타임라인            ├ 내 식물 공개
 ├ 날씨/할일 카드     ├ 식물 목록          └ 주간 요약(AI)       ├ 약관/개인정보
 └ 일괄 물주기        └ 상세 ─ 커뮤니티                         └ 로그아웃/탈퇴
```

**보조 화면**: 로그인 / 식물 등록·수정(bottom sheet) / 식물 상세(+기록 액션시트) / 사전 상세 / 식물별 커뮤니티 / 기록 작성·수정

## 3. 메뉴별 기능 정의

### 3-1. 내 식물 (홈)
- 상단 카드: 날씨(OpenWeather) / 물주기 대상 "N개 있어요" + **일괄 물주기** / 내 식물 요약
- 식물 카드: 이미지, 애칭, 물주기 D-Day(지남/오늘/남음), 원터치 물주기 버튼, (레벨 표시 — D-4)
- 내부 탭: 내식물 / 일정(다가오는 물·영양제·분갈이 예정) / 다이어리(사진·메모·상태 필터 + 프리뷰)
- 식물 등록: 식물종 검색(최근 검색어) → 애칭 → 대표사진 → 관리 기준 11항목 (생일, 마지막 물준날, 물·영양제·분갈이 주기, 햇빛·수분 선호 5단계, 온도 범위, 화분, 메모)
- 식물 상세: 히어로 이미지, D-Day 카드(물/영양제/분갈이/추가 알림), 요약 체크리스트, 기록하기 버튼
- 기록 액션시트 6종: 물주기 / 영양제(주기>0시) / 분갈이(주기>0시) / 메모 / 사진 / 상태(좋음·보통·관심 필요)
- 관리 종료 / 관리 재시작 (레거시 "죽음 처리"의 개선판)
- 레거시 계승 디테일: 물주기 확인 다이얼로그 + 완료 스낵바, 물주기 직후 리뷰 유도, 빈 상태 온보딩

### 3-2. 사전
- 검색(오타 보정은 AI 후순위) → 오늘의 식물 → 추천 섹션 10종(초보/공기정화/인테리어/반려동물 주의/아이 주의/물 좋아함/햇빛 좋아함/따뜻한 곳/최근 업데이트/인기)
- 상세: 기본 정보 / 관리 정보(물·햇빛·수분·온도) / 추천·주의 라벨 / 관리 팁 / 비슷한 식물 / **이 식물을 키우는 사람들**(공개 설정 유저) / 커뮤니티 진입("{식물명} 이야기")
- 도감 데이터: 레거시 자체 서버의 식물종 DB(약 124종+)를 Firestore로 이관

### 3-3. 기록
- 상단 자연어 입력 "오늘 어떤 돌봄을 했나요?" → **AI 초안**(식물명 매칭 + 유형 다중 추출 + 메모) → 사용자 확인 후 저장 (자동 저장 금지)
- 필터 7종(전체/물/영양제/분갈이/메모/상태/사진) + 날짜별 타임라인(세로선+도트)
- 메모·상태만 수정 가능, 모든 기록 소프트 삭제, pull-to-refresh
- 주간 돌봄 요약 (AI 2순위, 저장된 기록만 기반)

### 3-4. 계정 / 커뮤니티
- 계정: 프로필(아바타·이름) / 닉네임 수정 / 알림(푸시 on-off + 시각) / 내 식물 공개(`is_public`) / 약관 / 로그아웃 / 회원탈퇴
- 커뮤니티(식물별, 사전 상세에서만 진입): 글 목록 / 작성 / 상세 / 1단 댓글(수 집계+푸시) / 작성자 삭제 / **신고·차단 최소 구현**(스토어 심사 요건, 레거시 교훈)

### 3-5. AI 로드맵 (우선순위 확정안 — AI 보드 계승)
| 순위 | 기능 | 위치 | 원칙 |
|---|---|---|---|
| 1 | 자연어 기록 초안 | 기록 탭, 식물 상세 액션시트 | 자동 저장 금지, 기존 저장 흐름 재사용 |
| 2 | 주간 돌봄 요약 | 기록 탭, 다이어리 | 저장된 기록만 기반 |
| 3 | 내 식물 맞춤 사전 설명 | 사전 상세 | 사전 기준 vs 내 기록 차이 설명, 단정 진단 회피 |
| 4 | 커뮤니티 글쓰기 보조 | 식물별 커뮤니티 | 기록 요약 수준 |
- 기술 원칙: API 키는 클라이언트에 두지 않음(Cloud Functions 경유), 사용자별 요청 제한, 민감 원문 장기 보관 금지

## 4. 기술 아키텍처 (제안)

| 항목 | 레거시 | 차기 |
|---|---|---|
| 프레임워크 | Flutter 1.22 | Flutter 최신 stable (D-8에서 확정) |
| 상태관리 | 전역변수+setState | plantgram2의 GetX+Repository 계승 또는 Riverpod (D-8) |
| 백엔드 | 자체 Node(HTTP 평문) + Firebase 0.x 이중 | **Firebase 단일** (Firestore + Functions + Storage + FCM + Auth) |
| 데이터 원본 | 로컬 SQLite 우선 | **Firestore 단일 원본** + 오프라인 캐시 → 재설치 복원 문제 원천 해결 |
| 인증 | 5종 소셜+이메일 | Kakao 단일 (+Apple: D-1) |
| AI | 없음 | Cloud Functions → Claude/LLM API |
| 어드민 | 앱 내 탭 | Firebase 콘솔 (+필요 시 웹 대시보드) |

**주요 컬렉션(안)**: `users` / `myplants`(is_public, 관리기준 11항목, 상태) / `plant_actions`(6종, soft delete) / `plant_species`(도감) / `plant_tips` / `community_posts`+`comments`(식물별) / `ai_drafts`(임시)

## 6. 범위 단계 (제안)

- **M1 — 관리 코어**: 로그인, 식물 등록/수정, 홈(D-Day+일괄 물주기), 기록 6종, 일정/다이어리, 푸시
- **M2 — 사전**: 도감 이관, 검색, 추천 섹션, 상세+팁
- **M3 — AI 1·2순위**: 자연어 기록 초안, 주간 요약
- **M4 — 소셜 라이트**: 내 식물 공개, 키우는 사람들, 식물별 커뮤니티(+신고/차단)
- **출시 후 검토**: AI 3·4순위, 월간 캘린더, 통계, 매거진, 수익화, 다국어, 이미지 진단
