식물 아바타 — 등록하면 생기고, 키우면 자란다

자동 생성 + 커스텀
등록 시 식물종 기반 기본 아바타 자동 생성 (도감 124종+ → 형태 카테고리 12~15종 매핑). 커스텀 파츠: 화분(모양·색·패턴) / 크기 S·M·L / 잎 형태·색조 / 소품. 전부 무료, 일부는 레벨로 개방(수집 동기).
성장·상태 연동
레벨 구간마다 새싹 → 잎 전개 → 무성 → 만개로 성장. 물주기 지나면 잎이 처지고 물방울 말풍선. 제작은 레이어드 2D 에셋 조합(SVG) 권장 — AI 생성 초상화는 후순위 이벤트로.

정원 홈 — 아바타들이 사는 곳

내식물관리 홈에 정원 뷰 ↔ 리스트 뷰 토글. 창가·베란다 난간·선반·온실 배경에 아바타를 드래그 배치. 목마른 식물은 시든 모션 → 탭하면 바로 물주기(다마고치식). 실제 시간대·날씨 연동 배경 톤. 정원 스크린샷이 곧 피드 자랑 카드.

식물 GP → 식물 레벨(레벨업 시 토스식 폭죽 셀레브레이션 + 아바타 성장 + 피드 자랑 버튼 + 파츠 개방). 모든 식물 GP 합산 → 정원(계정) 레벨과 칭호(새싹 집사 → 정원사 → 식물 마스터), 배경 테마·프로필 프레임 개방.

가족 계정 — 점수를 같이 먹는 정원

한 계정이 절대 부모(소유자), 자식 계정은 초대 링크로 합류해 함께 편집·관리·기록. 공유 단위는 정원 단위. 자식의 활동 GP도 부모 정원 레벨에 합산 — 공동 레벨업, 셀레브레이션은 전 멤버에게. 멤버별 기여도 통계 + 개인 뱃지는 별도 적립. 기록에는 행위자 영구 표기.

AI 서비스 — 유료 허용으로 격상

AI-A · 식물 상태 리포트
지금까지 올린 사진 전체를 시계열 일괄 분석 + 기록·도감 기준 대조 → 성장 변화, 현 상태, 주의 신호(황변·잎끝 마름), 권장 조치. 단정 진단 회피 톤 유지.
AI-B · 환경 분석 (킬러 기능 후보)
식물이 놓인 자리 사진 촬영 → 채광·통풍·화분 배수 추정 → 이 식물 기준 과습·광부족 위험 안내 + 배치 개선 + "물주기 7일→9일" 원탭 주기 보정.

과금 제안(D-13): 무료 크레딧 월 N회 + 구독(플랜트그램 플러스). 자연어 기록·주간 요약은 무료 유지, 이미지 분석만 크레딧 차감. v0.1의 "이미지 진단 제외" 원칙은 공식 폐기.

기술 부채 (재사용 불가 판정의 근거)

  • Flutter 1.22 / Firebase 0.x — null-safety 이전 세대, 전면 마이그레이션 없이 빌드 불가
  • 백엔드 이중화: 평문 HTTP 자체 서버(65개 엔드포인트) + Firebase 혼용
  • 로컬 SQLite 우선 + Base64 이미지 저장 → 재설치 복원·마이그레이션 지옥
  • 전역 변수 + 타 화면 setState 직접 호출, 4,400~5,000줄짜리 단일 파일

02세 번의 시도가 이미 합의한 것

preview 저장소의 브리프(5/30) → AI 기획 보드(6/1) → 소스 기반 목업(6/1)은 경쟁안이 아니라 "무엇을 → 무엇부터 → 실제로 어디까지"의 3단 레이어였고, 핵심 결정은 한 번도 흔들리지 않았습니다.

하단 4탭 고정 — 내 식물 / 사전 / 기록 / 계정. 세 산출물 모두 동일.
커뮤니티는 식물 맥락형 — 독립 탭이 아니라 사전 상세에서 진입. "전체 게시판으로 확장하지 않는다" 3회 명문화.
AI 1순위 = 기록 탭 자연어 초안 — "몬스테라 물 줬고 새잎이 올라왔어" → 초안 생성 → 사용자 확인 후 저장(자동 저장 절대 금지). 예시 문장까지 세 번 동일.
레거시 절단 합의 — 쇼핑·중고거래·클래스·상담·QR·결제·관리자는 어느 산출물에도 재등장하지 않음.

한 가지 중요한 발견: 소스 기반 목업이 plantgram2 코드를 직접 읽으며 기획 문서에 없던 구현을 확인했습니다 — Lv.N 레벨 시스템, 일괄 물주기, 관리 종료/재시작, 상태 3단계(좋음·보통·관심 필요), 날씨 카드. 즉 plantgram2는 문서가 말하는 것보다 많이 만들어져 있습니다.
