# 스프라이트로 바꿀 때 Flutter에서 되는 것 · 안 되는 것

코드로 그리던 판(garden-kit)을 생성 이미지로 바꾸면 무엇이 달라지는지 정리합니다.
숫자는 전부 실제로 재본 값입니다.

## 1. 렌더링

지금은 아바타 한 그루가 `path` 200~670개입니다. 정원에 20그루면 프레임마다
수천 개를 그립니다. 스프라이트로 바꾸면 **한 그루가 이미지 2장**(식물 + 화분)입니다.

```dart
// 여러 스프라이트를 한 번에 — 정원 씬처럼 수십 개를 그릴 때
canvas.drawAtlas(atlasImage, transforms, sourceRects, colors,
                 BlendMode.modulate, null, paint);
```

`drawAtlas`는 한 번의 호출로 수백 장을 그립니다. 지금의 `CustomPainter` 경로보다
훨씬 쌉니다.

깊이 정렬은 지금과 같습니다 — 타일 좌표 `(i + j)` 오름차순으로 뒤에서 앞으로.

## 2. 화분 색 커스텀 — 지킬 수 있습니다

회색 화분 스프라이트에 색을 **곱하면**(modulate) 음영이 그대로 남은 채 색만 바뀝니다.
잘라낸 스프라이트로 직접 실험해 확인했습니다.

```dart
ColorFiltered(
  colorFilter: ColorFilter.mode(potColor, BlendMode.modulate),
  child: Image.asset('assets/sprites/pots/pot_bowl.webp'),
)
```

그래서 **화분은 무채색으로 받아야 합니다**. 색이 들어간 화분을 받으면
곱하기가 원래 색과 섞여 탁해집니다.

**중요** — 식물과 화분이 한 이미지면 화분을 물들일 때 **식물까지 같이 물듭니다**.
이것이 둘을 나눠 받아야 하는 이유입니다.

## 3. 잎 색 커스텀 — 포기해야 합니다

지금은 `tone`(기본초록 / 진초록 / 연초록 / 무늬종 / 실버) 5종을 코드로 즉시 바꿉니다.
스프라이트에서 같은 걸 하려면 종마다 5장을 따로 받아야 합니다 — 20종 × 4단계 × 5색 =
400장. 현실적이지 않습니다.

**대안**: 종마다 색을 고정하고(유칼립투스는 은청, 대나무는 황록), 색 대신
**화분·소품·바닥**으로 꾸미게 합니다. 실제로 꾸미는 재미는 그쪽이 더 큽니다.

## 4. 상태 표현 (건강 / 목마름 / 관리종료)

지금은 CSS 필터입니다. Flutter에서도 그대로 됩니다.

```dart
// 목마름 — 채도를 낮춥니다
ColorFiltered(colorFilter: ColorFilter.matrix(saturation(0.7)), child: sprite)
// 관리종료 — 회색조 + 반투명
Opacity(opacity: .55, child: ColorFiltered(
  colorFilter: const ColorFilter.matrix(greyscale), child: sprite))
```

## 5. 용량 — 실측

잘라낸 스프라이트 12장을 @3x(234px)로 줄여 재봤습니다.

| 형식 | 장당 평균 | 120장 기준 |
|---|---|---|
| PNG | 59 KB | 약 7 MB |
| **WebP q90** | **21 KB** | **약 2.5 MB** |
| WebP q80 | 18 KB | 약 2.1 MB |

**WebP q90을 쓰면 120장에 2.5MB 대**입니다. Flutter는 WebP를 기본 지원하고
알파도 유지됩니다. 앱 번들에 넣을 만한 크기입니다.

격자 한 칸이 78px이므로 @3x = 234px면 충분합니다. 그 이상은 용량만 늘어납니다.

필요한 장수 추정:
- 식물 20종 × 4단계 = 80
- 화분 10 + 지형 타일 8 + 온실 부품 10 + 소품 12 = 40
- **합계 약 120장 → 2.5MB**

## 6. 잃는 것 — 정직하게

| | 지금 (코드) | 스프라이트 |
|---|---|---|
| 화분 색 | 자유 (임의 색) | **지킴** (회색 + 곱하기) |
| 잎 색 5종 | 즉시 | **잃음** (종별 고정) |
| 새 종 추가 | 코드 한 벌 | 그림 4장 생성 + 자르기 |
| 앱 용량 | 0 (코드) | +2.5MB |
| 그림 품질 | 낮음 | **높음** |
| 남의 정원 열기 | ID만 전송 | **ID만 전송 (동일)** |

**남의 정원을 열 때 이미지를 주고받지 않는 구조는 그대로입니다.**
스프라이트는 앱에 미리 들어 있고, 서버는 지금처럼 `{종, 단계, 화분, 화분색, 위치}`만
보냅니다. 이 점은 하나도 바뀌지 않습니다.

## 7. 아바타 데이터 — 무엇이 바뀌나

```
지금   { form, stage, pot, potColor, tone, prop, state }
바뀜   { species, stage, pot, potColor, prop, state }
                ↑ form 대신 종         ↑ tone 삭제
```

`form`(형태 8종)이 `species`(종)로 바뀌고 `tone`이 빠집니다.
`potColor`는 남습니다 — 회색 화분에 곱하기로 살렸기 때문입니다.

기존 저장 데이터는 `form → species` 매핑표 하나로 옮길 수 있습니다
(대엽형 → 몬스테라, 직립형 → 산세베리아 …).

## 8. 순서

1. **식물 시트 한 장**을 위 프롬프트로 받아 자르고 앱에 넣어 한 그루만 띄워봅니다
2. 화분 시트(회색)를 받아 곱하기 색이 실제로 예쁜지 확인합니다
3. 괜찮으면 성장 4단계 × 대표종으로 넓힙니다
4. 지형·온실·소품은 그다음입니다 — 식물이 확정돼야 톤을 맞출 수 있습니다

1·2번이 반나절이면 끝납니다. 거기서 판단하는 게 안전합니다.
