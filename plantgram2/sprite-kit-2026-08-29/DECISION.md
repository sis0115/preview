# 결론 — 이미지 에셋을 조합하는 방식으로 간다

2026-08-29 확정.

## 결정

식물·화분·타일을 **생성 이미지로 받아 앱이 실시간으로 겹칩니다.**
Flutter에서 Path로 직접 그리는 방식은 접습니다.

**근거는 잎 품질입니다.** 코드로 그린 잎은 베지어 두 개로 만든 단순한
형태라, 생성 이미지의 잎을 못 따라갑니다
(`../garden-painter-2026-08-29/preview.png` 가 그 한계입니다).

크기 걱정은 실측으로 해소했습니다. 스프라이트를 실제 게임 크기인
96px로 줄여도 종이 구별되고 형태가 읽힙니다. 뭉개지지 않습니다.

## 왜 지난번엔 실패했나

시트를 **여러 번에 나눠 받았기 때문**입니다. 생성기는 "첨부한 것과
똑같이"를 느슨하게만 따릅니다. 받은 시트들의 실측값:

| | 등각 비율 | 채도 | 명도 |
|---|---|---|---|
| 화분 식물 | 2.82 : 1 | 0.55 | 0.62 |
| 지형 타일 | 1.56 : 1 | 0.49 | 0.21 |
| 온실 배경 | 1.64 : 1 | 0.27 | 0.68 |
| **목표 (기존 앱)** | **1.64 : 1** | **0.09** | **0.89** |

한 화면에 놓으면 세 세계가 섞입니다. 그런데 **한 이미지 안에 그린
47종은 완벽히 일치했습니다.** 이게 유일하게 믿을 수 있는 지렛대입니다.

그리고 저는 어긋난 시트를 매번 코드로 기웠습니다. 숫자는 맞췄지만
그림은 안 맞았습니다. **기우지 말고 되돌려보내야 합니다.**

## 다시 할 때 지킬 세 가지

1. **한 장에 최대한 많이 담는다.** 같은 그림 안에 있으면 각도·화풍·
   채도가 저절로 맞습니다. 나눠 받은 것끼리는 맞은 적이 없습니다.
2. **기준 시트를 먼저 확정한다.** 온실·타일·화분 식물을 한 장에 함께
   받아 통과시킨 뒤, 이후 모든 시트는 그 한 장을 첨부합니다.
   프롬프트: `prompts/k1_style_key.txt`
3. **숫자로 받고 숫자로 거른다.** `tools/gate.py` 를 통과하지 못하면
   채택하지 않습니다. 코드로 보정하지 않습니다.

```
python3 tools/gate.py sheets/<시트>.png --iso
```

## 그대로 쓰는 것

화풍과 무관하게 도는 도구들입니다. 새 그림이 오면 이 순서로 정원이
다시 나옵니다.

| | |
|---|---|
| `tools/check.py` | 투명도·덩어리 수·팔레트 검사 |
| `tools/gate.py` | 채도·명도·등각 비율 합격선 |
| `tools/slice.py` | 낱개로 자르기 (밑선 기준 행 정렬, 덩어리 마스킹) |
| `tools/deshadow.py` | 구워진 접지 그림자 제거 |
| `tools/grade.py` | 톤 보정, 타일 옆면 깎기 |
| `tools/compose.py` | 흙 무게중심과 밑동을 맞춰 겹치기 |
| `tools/scene.py` | 등각 격자에 깔고 (i+j) 순서로 그리기 |
| `tools/export_flutter.py` | WebP + 정렬점 JSON 내보내기 |
| `../garden-app` | Flutter 앱 (심기·물주기·화분 바꾸기·바닥 깔기) |

## 규격

- 등각 비율 **1.64 : 1** — 바닥 마름모, 화분 흙 타원, 전부 동일
- 톤 **채도 0.09 · 명도 0.89** 근처
- 화분 폭 100일 때 성체 잎 **폭 160 · 높이 180** (1.6배를 넘으면 옆 칸 침범)
- 타일 옆면 두께 = 윗면 높이의 **8%** 이하
- 식물은 화분 없이, 밑동을 수평으로 자르고 줄기가 절단선 가로 한가운데
- 화분은 빈 채로, 흙 윗면이 평평한 타원으로 드러나게
