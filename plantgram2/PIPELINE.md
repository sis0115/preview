# 조각을 수백 개로 늘리는 법

지금 스무 개를 만드는 데 쓴 방법으로 이백 개를 만들 수는 없습니다.
무엇이 막히는지 재 보고, 무엇을 바꿀지 적습니다.

## 1. 무엇을 고치는가 — 다시 확인

**앱은 `plantgram2/app` 입니다.**
`preview-seven-woad.vercel.app/plantgram2/app/` 에 올라가 있고, 빌드 안에
`<base href="/plantgram2/app/">` 가 박혀 있습니다.

앞서 이 문서는 `sis0115/plantgram`(오래된 플러터 앱)을 재고 있었습니다.
**틀렸습니다.** 그건 다른 앱입니다. 아래는 진짜 앱을 띄워 보고 잰 값입니다.

### 화면

| 탭 | 내용 |
|---|---|
| 피드 | 뱃지 · 기록 · 댓글 |
| **내 식물** | **우리집 온실 Lv.9 · 8030/8100 GP** |
| 도감 | 종 검색 · 테마별 (초보 11종 · 공기 14종 · 반려동물 17종 · 물 7종) |
| 계정 | 뱃지 7/15 · 함께 쓰는 온실 · 가드너 초대 |

온실 화면에는 이미 있습니다 — 등각 온실, 바닥 타일, 유리 골조, 화분 식물,
벤치·수레·선반·덤불, **D-day 물주기 말풍선**, 식물 누르면 "아이비 Lv.2",
카메라(끌기 · 핀치 · ＋/−/맞춤), **돌보기 / 꾸미기** 두 모드.

### 지금 그림은 전부 **코드**입니다

빌드의 에셋을 열어 보면 **폰트 여덟 개가 전부**입니다. 그림 파일이 한 장도
없습니다. `garden-painter-2026-08-29/garden_painter.dart` 가 그 방식을
스스로 적어 두었습니다.

> 스프라이트를 한 장도 쓰지 않습니다. 타일도 화분도 잎도 전부 Path 로
> 그립니다. 그래서 종·단계·색을 숫자로 바꾸면 그림이 따라 바뀝니다.

바로 이 문장이 바꿀 것이자, 잃을 것입니다.

| | 코드로 그리기 (지금) | 그림 얹기 (하려는 것) |
|---|---|---|
| 종을 늘릴 때 | 숫자 몇 개 · **공짜** | 그림 한 장씩 · **돈과 시간** |
| 생김새 | 도형의 한계 | 실제 그림 |
| 앱 크기 | 0 | 종마다 수백 KB |
| 바꾸기 | 코드 수정 | 다시 받기 |

**공짜였던 것이 공짜가 아니게 됩니다.** 그래서 몇 장이 필요한지를 먼저
세야 합니다(§5).

### 숫자 두 개가 다릅니다

| | 바닥 타일 | 등각비 |
|---|---|---|
| 앱 (`garden_painter.dart`) | 156 × 95.1 | **1.64 : 1** |
| 우리 그림 (`app-kit`) | 156.8 × 90.7 | **1.73 : 1** |

5% 차이입니다. 앱 쪽은 코드라 고치면 그만이고, 그림은 고칠 수 없습니다.
**앱이 1.73 으로 옵니다**(RULES 11.5 — 등각비는 그림이 정합니다).

### 가장 큰 걸림돌 — 소스가 없습니다

이 리포에는 `plantgram2/app/` **빌드만** 들어 있습니다. 커밋 메시지도
"빌드 갱신 — 소품 다리·바퀴, 선반 5칸" 처럼 밖에서 만들어 넣은 모양입니다.
리포 전체에 이 앱의 `.dart` 파일이 하나도 없습니다.

**소스 없이는 앱을 못 고칩니다.** 먼저 해결해야 할 것은 이것입니다.

## 2. 바꾸는 원칙 하나

> **적는 값과 재는 값을 나눈다.**

* **적는 값** — 무엇을 만들 것인가. 이름, 종류, 등급, 자리의 뜻.
  사람이 씁니다. `asset-pipeline/registry.json` 한 곳.
* **재는 값** — 폭, 높이, 기준점, 밑면 칸수, 자리 좌표.
  **그림에서 잽니다.** 사람이 쓰지 않습니다. 쓰면 반드시 어긋납니다.

지금까지 난 사고는 거의 전부 이 둘을 섞어서 났습니다. 칸 수를 폭으로
정했고(방향을 놓침), 판 높이를 반올림한 칸 수로 쟀고(31px 가라앉음),
자리 높이를 안내 이미지에 적어 보냈습니다(지켜지지 않음).

## 3. 여섯 단계

```
 등록          계획              요청        받기      검사        빌드
registry.json → plan.py → 안내 이미지+글 → 그림 → gate.py → build → 앱
   (사람)      (자동)        (자동)      (사람)   (자동)    (자동)
```

| 단계 | 도구 | 하는 일 |
|---|---|---|
| 등록 | `registry.json` | 만들 조각을 적습니다. 이것만 사람이 씁니다. |
| 계획 | `tools/plan.py` | 열한 개씩 묶고 **시트마다 기준 조각**을 넣습니다 |
| 요청 | (계획에서 생성) | 안내 이미지와 요청문 |
| 받기 | — | 그림을 받아 `sheets/` 에 둡니다 |
| 검사 | `tools/gate.py` | 잘라서 재고 **합격/불합격을 기계가 정합니다** |
| 빌드 | `tools/build.py` | 앱 에셋과 카탈로그 |
| 보기 | `tools/contact.py` | 라이브러리 한 장 (`web/library.html`) |

## 4. 합격 기준 — 숫자로

`tools/gate.py` 의 `RULE`. 통과 못 하면 **들이지 않습니다.**

| 기준 | 값 | 왜 |
|---|---|---|
| 배경 잔재 | ≤ 0.30% | 잎 사이 흰 종이 |
| 최소 크기 | ≥ 3,000px | 잘못 잘린 조각 |
| 기준 조각 | ±6% 이내 | 이게 틀리면 시트 전체 축척을 못 믿습니다 |
| 등급 간격 | ≥ 1.08배 | 소형과 중형이 같아 보이면 등급이 아닙니다 |
| 조각 수 | 정확히 일치 | 하나 붙어 오거나 빠진 것 |

시험해 봤습니다.

* 빈 가구 시트 → **합격**
* 빛 번짐 시트 → **불합격** (예전에 제가 눈으로 "쓸 수 있을까" 고민했던 것)
* 기준 조각 뺀 시트 → **불합격**

## 5. 규모 — 몇 장이 필요한가

도감에 테마별로 11 + 14 + 17 + 7 종이 보입니다. 겹치는 것을 빼도 **서른
종 안팎**입니다. 등급이 다섯이면 종만 150장이고, 화분·가구·배경이 따로
붙습니다.

**단계를 다섯에서 셋으로 줄이면 크게 달라집니다.**

| | 5단계 | **3단계 (새싹 공용)** |
|---|---|---|
| 30종 | 150장 | **61장** |
| 시트(11개씩) | 15장 | **6장** |
| 왕복 | 15~30번 | **6~12번** |

새싹은 종을 가리지 않습니다 — 떡잎 두 장은 몬스테라나 고사리나 비슷합니다.
**새싹 한 장을 모든 종이 함께 쓰고**, 종마다 `자람 / 다 자람` 두 장만
받으면 61장입니다. 이미 가진 것이 16장이니 45장이 남습니다.

등급 다섯은 **화분** 쪽에만 두면 됩니다. 화분은 다섯 장이면 끝이고, 이미
다 있습니다.

`plan.py` 로 세어 보면:

```
가진 것 16개 · 만들 것 24개 · 시트 5장
```

한 시트 = 한 번 요청. 왕복 1~2회면 **5~10번**입니다. 지금까지 조각 16개에
열 번 넘게 주고받은 것에 비하면 한 번에 나가는 양이 다섯 배입니다.

**왜 열한 개인가** — 열두 개부터 한 시트 안에서 크기가 흔들렸습니다.
한 장 안에서 그린 것끼리는 축척이 저절로 맞는다는 전제가 깨집니다.

## 6. 앱에 얹는 법

### 6.1 그리는 방식 — 3D 를 쓰지 않습니다

이미 증명됐습니다. 등각 그림 한 장 + 규칙 몇 줄로 배치·회전·앞뒤·자리가
다 됩니다.

| | 3D (모델·엔진) | 등각 스프라이트 (지금) |
|---|---|---|
| 조각 만들기 | 모델링·리깅·조명 | 그림 한 장 |
| 앱 크기 | 엔진 + 모델 | PNG 몇 MB |
| 낡은 기기 | 버겁습니다 | 캔버스 그리기 |
| 바꾸기 | 모델 다시 | 그림만 갈아 끼움 |
| 화풍 | 맞추기 어렵습니다 | 한 시트 안에서 저절로 |

회전이 필요하면 **좌우로 뒤집습니다** — 등각에서는 그게 곧 90도
돌리기입니다(RULES 1.6). 방향마다 그림을 새로 받지 않습니다.

### 6.2 코드를 어디에 두나

앱 소스가 이 리포에 없습니다. 셋 중 하나를 먼저 정해야 합니다.

1. **소스를 리포에 넣는다** — 가장 낫습니다. 넣으면 제가 고치고 빌드까지
   합니다. 지금은 빌드만 오가서, 제가 고친 것이 앱에 들어갔는지 확인할
   길이 없습니다.
2. 소스는 밖에 두고 **정원 부분만 패키지로** 주고받는다 — `app-kit` 을
   `garden_kit` 으로 이름 바꿔 넘기면, 앱에서 `path:` 나 git 으로 물립니다.
3. 아무것도 못 할 때 — 웹판(`web/greenhouse.html`)을 WebView 로. 같은
   카탈로그를 쓰므로 그림은 한 벌로 끝납니다. 임시방편입니다.

어느 쪽이든 **정원 그리는 부분은 앱 본체와 떼어 둡니다.** 지금 앱은
그리기가 코드 안에 박혀 있어, 그림으로 바꾸려면 그 파일을 통째로
갈아야 합니다.

### 6.2.1 코드 그리기 → 그림 얹기, 무엇을 남기나

전부 그림으로 바꾸지 않습니다. **변하는 것은 코드, 생김새는 그림.**

| 그림으로 | 코드로 남김 |
|---|---|
| 식물 · 화분 · 가구 · 배경 | 바닥 격자 · 선택 테두리 |
| | D-day 말풍선 · Lv 뱃지 |
| | 접지 그림자 · 카메라(끌기·확대) |
| | 물주기 효과 · 자라는 애니메이션 |

지금 웹 시험대가 이미 그 모양입니다 — 그림은 얹고, 격자·표시·그림자는
코드가 그립니다. 앱에 옮길 때 이 경계를 그대로 씁니다.

### 6.3 에셋을 어떻게 싣나

| 조각 수 | 방법 |
|---|---|
| ~80 | 폴더 선언 (`- assets/garden/`) · 지금 방식 |
| 80~300 | **아틀라스** 한 장 + 좌표표. 첫 화면이 느려지면 넘어갑니다 |
| 300~ | 종류별 아틀라스 + 필요할 때 내려받기 |

`Image.asset('assets/1.png')` 를 코드에 쓰지 않습니다. 언제나
**카탈로그를 거칩니다.** 그래야 그림을 갈아 끼울 때 코드를 안 고칩니다.

## 7. 이름과 판

* 이름은 **뜻으로** — `pot_medium`, `monstera_large`, `shelf_two`.
  `1.png` 같은 이름은 지울 수도 바꿀 수도 없습니다.
* 조각마다 **어느 시트에서 왔는지**(`sheet`) 적어 둡니다. 한 조각이
  이상하면 같은 시트의 다른 조각도 의심합니다.
* 한 조각만 다시 받을 때는 **그 조각 + 기준 조각**만 요청합니다
  (RULES 11.11). 멀쩡한 것까지 걸지 않습니다.

## 8. 다음에 할 것 — 차례대로

1. **앱 소스를 어디에 둘지 정합니다** (§6.2). 이게 먼저입니다. 나머지는
   전부 이것에 걸려 있습니다.
2. 앱의 등각비를 1.64 → **1.73** 으로 맞춥니다. 코드 한 줄입니다.
3. 종 단계를 다섯에서 **셋**으로 줄일지 정합니다 (§5). 장수가 150 → 61 로
   바뀝니다.
4. 그리기 경계를 긋습니다 (§6.2.1) — 그림으로 갈 것과 코드로 남길 것.
5. 첫 종 한 가지를 시트로 받아 앱에 얹어 봅니다. 한 종이 끝까지 가면
   나머지는 같은 길입니다.
